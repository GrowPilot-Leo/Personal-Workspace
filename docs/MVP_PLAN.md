# GrowPilot MVP 开发计划

## 1. 决策

MVP 采用移动端优先的 Web/PWA，先验证“目标 → 今日行动 → 记录 → 反馈 → 调整”闭环。Android 1.0 在闭环稳定后选择 Web 容器封装或 Expo/React Native；业务规则和数据契约避免绑定具体 UI 技术。

## 2. 第一阶段范围

- 设置一个阶段目标和当日可用时间。
- 创建 1～3 个今日任务，记录预计时长。
- 完成或撤销任务，展示真实完成度。
- 保存每日复盘：完成收获、阻塞原因、下次调整。
- 根据完成情况生成可解释的次日规则建议。
- 归档当日记录，未完成任务结转到下一天。
- Dashboard 只展示真实本地数据，不展示虚构成长分数。

## 3. 数据策略

首个可交互版本使用浏览器本地存储，便于在没有本地后端环境时验证流程。数据只存在当前浏览器和设备，清理浏览器数据会丢失；它不是生产数据方案。

生产阶段迁移到 PostgreSQL/Supabase 前，必须补充用户身份、授权、数据库迁移、数据导出与删除、保留期限和离线同步策略。

## 4. AI 边界

当前次日建议由透明规则生成，不伪装成 AI。接入模型前先建立服务端 AI Gateway、结构化输出校验、超时、错误记录和调用评测；API Key 不进入浏览器。

## 5. MVP 验收标准

1. 安卓手机浏览器可以完成目标设置、任务记录、复盘和次日结转。
2. 刷新页面后数据仍存在。
3. Dashboard 与 Learning 展示同一份真实状态。
4. 空数据、已完成、超出时间预算和复盘完成状态均有明确反馈。
5. 类型检查和生产构建在 GitHub Actions 中通过。
6. 功能通过 Draft PR 审核后才允许合并 `main`。

## 6. 暂不包含

登录、云端同步、RAG、多模型路由、医学建议、原生推送、相机、语音和应用商店发布。
