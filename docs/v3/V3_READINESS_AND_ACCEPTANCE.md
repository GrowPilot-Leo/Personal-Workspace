# GrowPilot V3 启动门禁与验收标准

状态：V3 开发前置基线  
制定日期：2026-08-06  
计划启动日期：2026-08-07  
基线分支：main  
基线提交：3104cc033012c803e32915eb96363131ab1beaa7  
适用范围：V3 稳定性阶段及后续所有 V3 功能 PR

## 1. 结论

V2 当前可以通过 41 项规则测试、TypeScript 类型检查和 Next.js 生产构建，但仍存在会直接影响用户使用的主题、移动端、交互、数据真实性和结构收束问题。

V3 不从新增 AI、RAG、Career、Fitness 或其他业务功能开始。V3 的第一个阶段必须是“稳定性与架构收束”。本文件中的 P0、P1 必须修改项全部通过后，才允许进入新增功能阶段。

V3 继续遵守已有产品决策：

- 不复制完整的 V1、V2、V3 应用。
- 不删除或静默覆盖 V1 数据。
- AI 输出在影响用户事实、计划或记忆前必须由用户确认。
- Today 只聚合其他模块的公开摘要，不直接拥有或修改其他模块的数据。
- 新学习主题是可配置 Learning Space，不新增硬编码业务模块。
- 真实能力未接通时使用诚实空状态或明确 Mock 标识，不伪装成真实完成度。
- 每次变更必须说明所属模块、数据影响、公共契约、迁移、验证和回滚路径。

## 2. 证据基线

### 2.1 已验证事实

- main 当前头提交为 3104cc0，标签为 v0.2.0-visual-refresh。
- npm test：41/41 通过。
- npm run typecheck：通过。
- npm run build：通过，15 个 App Router 路由完成静态生成。
- 本地生产预览没有运行时错误和 Next.js 错误覆盖层。
- 夜间主题浏览器计算值：主内容区背景为 rgb(255, 255, 255)，一级标题文字为 rgb(231, 239, 236)，存在接近白字白底的问题。
- 390×844 视口下，桌面侧栏仍占 248px，主内容只剩 142px，当前正式壳层没有移动端导航。
- Today 页“开始今日行动”按钮点击后没有导航、状态变化、弹窗或提示。
- 快捷 Prompt 点击后没有成功或失败提示；剪贴板错误被静默吞掉。
- Dashboard 的学习进度、项目进度、知识更新和最近复盘来自硬编码 demo 数组，界面没有统一的示例标识。
- 当前 UI 仍直接读取 growpilot.daily-loop.v1；V1→V2 migration、Event Bus 和 Feature Flags 尚未接入正式页面入口。
- 自动可访问性检查发现 Today 概览使用 role=list，但子节点缺少 listitem 角色。

### 2.2 基于事实的架构判断

- 当前问题不是单一 CSS Bug，而是新旧 AppShell、Dashboard、全局样式、主题变量和数据模型同时存在造成的边界不清。
- 现有 41 项测试可以证明核心规则和构建基线，但不能证明主题可读、按钮有效、移动端可用或浏览器 hydration 不回归。
- V2 提交已经修复全屏遮罩造成的薄雾和 hydration 中断，但主题硬编码白底、移动端壳层缺失和无动作按钮仍可复现。

### 2.3 待验证项

以下内容没有足够证据，不得写成已确认故障：

- 线上部署是否仍被旧 Service Worker 或浏览器缓存控制。
- 特定手机、浏览器和系统字体是否存在额外渲染问题。
- 线上真实数据是否与本地 V1 storage 结构完全一致。

验证方式：取得正式部署 URL、具体设备和浏览器版本后，执行本文的线上验收矩阵。

## 3. V3 必须修改项

## V3-001：统一主题和颜色系统

优先级：P0  
所属：Shared Theme / App Shell

必须修改：

- 只保留一种正式主题选择机制，统一使用 html[data-theme] 或经批准的单一等价方案。
- Day、Night、Dusk 的背景、文字、边框、卡片、输入框、弹窗和导航全部从语义 Token 获取。
- 删除内容组件中的 bg-white、text-zinc-* 等会绕过主题的硬编码，除非该颜色有经过记录的跨主题设计理由。
- 收束重复的 Tailwind 导入、主题 Token 和全局样式入口。
- ThemeProvider、首屏防闪脚本和服务端首屏状态必须使用同一默认值和同一存储规则。
- 不允许动画初始状态控制内容是否可见。

阻断验收：

- /dashboard、/today、/learning、/career、/english、/fitness、/review、/knowledge、/badge、/settings 在 Day、Night、Dusk 下均可阅读。
- 普通文字对比度不低于 4.5:1；大号文字和必要 UI 图形不低于 3:1。
- 不存在“浅色文字 + 白色主内容背景”或等价不可读组合。
- 刷新、直接访问深层路由和已有本地主题偏好三种场景均无 hydration 错误、白屏或主题闪烁导致的不可操作状态。
- 自动化主题截图覆盖桌面和手机视口，PR 中附对比结果。

## V3-002：恢复正式移动端壳层

优先级：P0  
所属：App Shell / Navigation

必须修改：

- 正式 AppShell 在手机端隐藏桌面侧栏。
- 使用底部导航、抽屉或经评审确认的单一移动导航方案。
- 所有九个固定入口在移动端均可访问。
- 桌面侧栏折叠状态不得影响手机端内容宽度。
- 手机端内容、弹窗和固定导航正确处理 safe-area。

阻断验收：

- 375×812、390×844、430×932、768×1024 四个视口全部通过。
- documentElement.scrollWidth 不得大于 viewport 宽度。
- 390px 视口下主内容不再被 248px 桌面侧栏挤压。
- 手机端可从 Today 到达其余八个入口，并能返回 Today。
- 导航点击区建议不小于 44×44px；键盘和触摸均可操作。
- 横竖屏切换后不得出现导航消失、内容遮挡或滚动位置锁死。

## V3-003：建立统一交互反馈契约

优先级：P0  
所属：Shared UI / 各业务模块

必须修改：

- 所有可见按钮必须满足以下之一：导航、提交、切换状态、打开弹窗、复制并反馈。
- 没有功能的入口不得呈现为正常可用主按钮。
- 暂未开放能力必须使用 disabled 状态并给出原因，或使用明确的“即将开放”空状态。
- 异步操作必须有 loading、success、error 三种状态。
- 剪贴板、localStorage、Service Worker 等浏览器 API 错误不得静默吞掉。
- 全局搜索要么实现最小搜索闭环，要么在 V3 稳定阶段明确禁用。

阻断验收：

- “开始今日行动”点击后产生已定义动作。
- 三个快捷 Prompt 均显示复制成功；拒绝剪贴板权限时显示失败提示。
- 全部路由的主要按钮逐一通过浏览器测试，不存在 enabled no-op button。
- 重复点击不会重复提交或产生不可恢复状态。
- 错误提示可被屏幕阅读器感知，并提供可执行的恢复动作。

## V3-004：移除未标识的虚构业务数据

优先级：P0  
所属：Dashboard / Data Truth

必须修改：

- 删除或隔离 demoLearningProgress、demoProjects、demoKnowledgeUpdates、demoReviews 等展示为真实业务结果的固定数据。
- 没有数据时展示真实空状态和下一步操作。
- 必须保留示例时，使用独立“示例模式”，在卡片和页面级明确标识，不与用户真实数据混合。
- 任何百分比、日期、风险状态和 AI 结论必须能追溯到真实记录、确定性规则或明确 Mock fixture。

阻断验收：

- 默认正式模式不展示无法追溯的学习百分比、项目风险或复盘记录。
- 每个数字都能说明来源字段和计算规则。
- 示例数据不会写入用户正式 storage。
- 测试不再以“demo 数组必须非空”作为产品正确性的证明。
- PR 审查中抽查 Dashboard 所有数字，来源不明即阻断合并。

## V3-005：收束界面结构和模块入口

优先级：P1  
所属：Architecture / Shared UI

必须修改：

- 只保留一个正式 AppShell。
- 只保留一个正式 DashboardModule。
- 只保留一个全局样式入口和一个主题 Token 体系。
- 明确区分导航展示元数据与模块业务 Manifest；如果保留两个 Registry，必须由单一来源生成或增加一致性测试。
- 旧实现的删除必须确认无引用，并使用小提交完成，不与业务功能混合。
- Shared UI 不承载业务判断；Routes 只组合模块公开 API。

阻断验收：

- 静态依赖检查证明正式路由只引用一个 AppShell 和一个 Dashboard。
- 不存在未使用但仍被全局 CSS 影响的旧壳层。
- 九个模块的 ID、路由、标签和 Manifest 无漂移。
- 其他模块只能从目标模块的 public.ts 导入。
- 每次结构删除都有构建、回归测试和清晰回滚提交。

## V3-006：正式接通 V2 数据边界

优先级：P1  
所属：Core / Persistence / Today / Learning

必须修改：

- React 页面和组件不得直接分散读写 localStorage。
- 建立 typed repository 或 persistence adapter。
- 在正式入口执行显式、幂等的 V1→V2 migration。
- migration 必须保留原始备份、记录版本和结果，不得静默覆盖 V1。
- V2 读模型必须验证反序列化结果；损坏数据不得导致白屏。
- Today 通过模块公开摘要聚合，不直接修改其他模块内部数据。

阻断验收：

- 有数据、无数据、损坏 JSON、重复迁移、中途失败五类测试全部通过。
- 重复运行 migration 不重复创建 Goal、Task、Review 或日志。
- migration 失败时不写入部分 V2 状态。
- 可通过明确回滚步骤继续读取 V1 备份。
- UI 正常路径不再直接引用 window.localStorage。
- 新数据写入使用 V2 schemaVersion，并记录必要的更新时间和来源。

## V3-007：补齐浏览器回归测试

优先级：P1  
所属：Engineering Quality

必须新增：

- 浏览器端 E2E 测试。
- 主题视觉回归。
- 桌面与移动端导航测试。
- 关键按钮反馈测试。
- hydration 和控制台错误检查。
- 可访问性自动检查。
- migration 集成测试。

最低覆盖矩阵：

| 维度 | 必须覆盖 |
|---|---|
| 路由 | Dashboard、Today、Learning、一个占位模块、Settings |
| 主题 | Day、Night、Dusk |
| 视口 | 1440×900、390×844 |
| 状态 | 空数据、正常 V1 数据、已迁移 V2 数据、损坏 storage |
| 交互 | 导航、主题切换、主按钮、Prompt 复制、错误恢复 |

阻断验收：

- CI 中运行浏览器核心流程，不只运行纯函数测试。
- 页面加载后无 console error、unhandled rejection 或框架错误覆盖层。
- axe 检查不得存在 critical 或 serious violation。
- Today 概览使用正确的列表语义。
- 主题截图差异必须由评审者确认，不能无说明更新基线图。

## V3-008：动效、PWA 和失败恢复

优先级：P1  
所属：Motion / PWA / Reliability

必须修改：

- full、reduced、off、system 同时作用于 CSS 和 Motion for React。
- off 模式不执行位移、缩放和渐变入场。
- system 模式遵守 prefers-reduced-motion。
- Service Worker 区分页面导航和静态资源，不得用 Dashboard HTML 回退 JS/CSS 请求。
- 注册、更新和离线失败必须有可诊断信息。
- Cache 名称和升级策略必须版本化并可清理旧缓存。

阻断验收：

- reduced/off 下浏览器测试证明 JS 动画和 CSS 动画均符合设置。
- 离线访问已缓存页面可用；未缓存页面显示明确离线状态。
- 静态资源请求失败时不返回 HTML。
- 新版本上线后能够激活新 Service Worker，且不会持续使用旧 UI。
- PWA 失败不影响在线核心流程，但错误可被记录和排查。

## 4. V3 开发门禁

## Gate A：开始编码前

以下条件全部满足才允许修改功能代码：

- 本文已由仓库所有者审核。
- 创建独立 V3 稳定性分支，不直接向 main 提交。
- 记录 main 基线提交和现有验证结果。
- 明确第一批 PR 只处理一个根因，不混入新业务功能。
- 每个任务写出失败测试或可重复浏览器步骤。
- 明确受影响模块、数据、公共契约、迁移和回滚方案。

## Gate B：单个 PR 合并前

每个 V3 PR 必须满足：

- 使用聚焦的 Conventional Commit。
- PR 描述包含：问题、根因、修改范围、数据影响、契约影响、迁移、验证、回滚。
- npm test、typecheck、production build 全部通过。
- 涉及 UI 时必须附桌面和手机验证。
- 涉及主题时必须附三主题验证。
- 涉及交互时必须附成功和失败路径。
- 涉及数据时必须附 migration 或说明无需 migration 的证据。
- 没有未解释的真实个人数据、Token、密钥和私有媒体。
- 不存在新增的 critical/serious 可访问性问题。
- 不允许用 suppressHydrationWarning 掩盖尚未定位的业务节点不一致。

## Gate C：V3 稳定性阶段退出

以下条件全部满足，才允许开发新的业务功能：

- V3-001 至 V3-004 全部完成。
- V3-005 至 V3-008 没有未处理的阻断项。
- P0、P1 缺陷为 0。
- 三主题、桌面、手机核心流程通过。
- 默认模式没有未标识的示例数据。
- enabled no-op button 数量为 0。
- 浏览器控制台错误数量为 0。
- axe critical/serious violation 数量为 0。
- V1 数据备份和 V1→V2 migration 已实际验证。
- 有明确回滚提交或功能开关。

## 5. 建议开发顺序

2026-08-07 开始 V3 时，按以下顺序推进：

1. 建立浏览器失败用例：夜间主题、390px 布局、无动作按钮。
2. V3-001：统一主题 Token 和内容背景。
3. V3-002：将已存在的移动导航能力迁入正式 AppShell。
4. V3-003：修复主按钮、搜索和复制反馈。
5. V3-004：移除或隔离未标识 demo 数据。
6. V3-005：删除确认无引用的旧 Shell、旧 Dashboard 和重复样式。
7. V3-006：接通 V2 repository、migration 和读取入口。
8. V3-007：把关键浏览器回归加入 CI。
9. V3-008：完成 motion preference 和 PWA 升级测试。
10. 通过 Gate C 后，再评审并加入新的 V3 产品想法。

同一 PR 不同时处理主题、数据迁移和新业务功能。每个根因单独测试、单独提交、单独评审。

## 7. V3 Definition of Done

一个 V3 任务只有同时满足以下条件才算完成：

- 用户场景和预期结果明确。
- 根因已验证，不是只修表面症状。
- 有修复前失败、修复后通过的自动测试或可复现证据。
- 成功、空状态、错误和恢复路径都已处理。
- 不展示无法追溯的数据或结论。
- 不破坏 V1 数据和现有核心闭环。
- 模块边界、公共契约和 migration 影响已记录。
- 桌面、手机、三主题和 reduced motion 按影响范围验证。
- CI、typecheck、build 通过。
- PR 有回滚方式，审查者可以独立复现结果。

只通过构建、不报类型错误、页面能打开，均不能单独视为完成。
