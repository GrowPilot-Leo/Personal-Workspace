# GrowPilot 2.0 迭代计划

## 1. 版本目标

2.0 不推翻已通过验收的每日成长闭环，而是在其上解决三个真实问题：

1. 数据可迁移：用户可以备份、恢复并升级本地数据，不再完全依赖单一浏览器存储。
2. 反馈可追溯：Dashboard 能基于真实历史记录展示趋势和执行依据。
3. 能力可扩展：为后续登录、云同步、AI 建议和 Android 封装建立稳定边界。

## 2. 第一里程碑：数据基础

- 为每日闭环状态增加明确的 schema version。
- 建立 storage adapter，业务规则不直接依赖 localStorage。
- 支持 JSON 导出、导入、校验和错误提示。
- 提供从 MVP 本地数据到 2.0 数据结构的无损迁移。
- 为迁移、导入和异常数据补充自动化测试。

### 验收标准

- 原有 MVP 数据升级后目标、任务、历史和复盘不丢失。
- 用户可以在设置页导出备份，并在另一浏览器恢复。
- 无效或超大备份不会覆盖当前有效数据。
- Dashboard 与 Learning 继续读取同一份状态。
- CI 的安全审计、测试、类型检查和生产构建全部通过。

## 3. 第二里程碑：历史与洞察

- 展示最近 7/30 天完成率、计划时长和实际闭环次数。
- 所有指标均来自真实记录，并清楚标注计算口径。
- 支持查看单日归档详情，不制造成长分数或虚假 AI 结论。

## 4. 第三里程碑：账号与云同步

先定义供应商无关的数据契约，再选择具体托管服务。候选方案为 PostgreSQL/Supabase，但在确认账号、费用、数据区域和权限模型前不直接绑定。

必须包含：

- 身份认证与最小权限授权；
- 行级数据隔离；
- 本地优先与冲突处理；
- 导出、删除、保留期限和恢复策略；
- 数据迁移与回滚方案。

## 5. 第四里程碑：AI 与 Android

- AI 建议只能通过服务端 Gateway 调用，密钥不得进入浏览器。
- 建议必须结构化、可解释、可关闭，并具备超时和降级。
- Android 先比较受控 WebView/Capacitor 与 Expo/React Native，再根据原生能力需求决定；不因封装重写业务规则。

## 6. 分支与审核规则

- 当前开发分支：`codex/v2.0-foundation`。
- 所有变更通过 Draft PR、CI 和 Vercel Preview 验证。
- 每个提交使用明确的类型、范围和目的注释。
- 未经仓库所有者完成 2.0 阶段验收并明确批准，不合并 `main`。
